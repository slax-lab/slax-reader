# Design

## Context

See proposal.md for the requested presentation. `FeedbackScreen` already receives form state and submission through `useFeedback`, uses the native navigation header, and measures the surface for keyboard avoidance. `TextAction` already supplies disabled styling and accessibility. Existing mounted tests invoke a footer action and assume the header only dismisses the keyboard; those assumptions must change with the UI.

## Goals / Non-Goals

**Goals:** Keep presentation in `FeedbackScreen`, reuse existing controls and translations, and preserve the current feedback controller and lifecycle ownership.

**Non-Goals:** Transport changes, diagnostic policy changes, global touch handling, new libraries, and layout changes outside the requested Feedback and Reader menu surfaces.

## Decisions

- Use `navigation.setOptions` to render the existing `TextAction` as header Submit, with dependencies on current content validity, pending/ownership state, submit callback, and translation. Reuse its test ID. Remove the footer and explicit dismiss controls; screen unmount already cancels through the controller lifecycle.
- Put the flexible editor scroll area and a nonshrinking consent group beside each other vertically in a bounded form. The editor fills remaining height with a 96-point usable minimum; its input fills that frame absolutely so long text cannot enlarge it. Text scrolls internally; when an unusually short viewport cannot fit article context plus the minimum editor, only that upper area can scroll while consent stays pinned. Keep the measured native-header offset, existing KeyboardAvoidingView, and ScreenSurface safe-area ownership. Use 16-point form padding above the safe area or keyboard. Preserve ScrollView background-tap dismissal; a non-accessible form Pressable covers outer padding without adding a screen-reader button. Consent Pressables are outside the ScrollView and handle their own taps; remove their explicit Keyboard.dismiss calls so toggling preserves the existing input focus, cursor, and keyboard state without a blur/refocus cycle.
- Four approaches were compared after the geometry check exposed footer displacement: a single bounded form (editor padding still overflowed a short viewport), explicit measured editor heights (extra state and resize bookkeeping), an absolutely positioned footer (requires measuring footer height), and a fixed footer beside a flexible scroll area (chosen, no added state or keyboard listeners). A long input is excluded from intrinsic parent sizing so it cannot push the footer down. Native touch/keyboard transitions remain part of owner acceptance.
- Keep current option state defaults and hook behavior. Render follow-up, a Mobile-token divider, then attachment with matching 14-point typography and 12-point circular artwork. Keep the row's 48-point minimum touch height. Per the owner's hands-on feedback, checked and unchecked attachment states show the same concise visible label; retain the existing accessibility hint without rendering another text block.
- Extend the existing mounted-test navigation stub to render the header action. Continue invoking actual screen/controller behavior and existing transport fixtures; do not replace it with source-text assertions or a parallel test form.
- Reader More-panel tiles already measure 56 by 56 logical points. Keep that geometry and move the decorative Pro badge to `top: 0` with horizontal self-centering inside the tile. The original image is 100 by 40 pixels; retain its 24-point visible width and use a 9.6-point image height so its visible artwork aligns with the top instead of being vertically letterboxed within a square. Existing menu behavior tests suffice for this local style correction; native visual acceptance remains with the owner.
- Render the tiles' action icons at 24 by 24 logical points through the existing shared SourceIcon size prop, replacing 28 points. This applies equally to standard, selected, YouTube, and PDF action variants; tile dimensions, hit targets, label spacing, and Pro badge sizing remain unchanged.
- HTML/PDF CSS selects with `#8AD8A866` and matching opaque `caret-color`. The owner found that this CSS-only change did not affect their native iOS selection. Set Reader WKWebView.tintColor explicitly to RGB `(138, 216, 168)` in its initializer through the public UIKit property. Native opacity remains system-controlled; the retained CSS serves document rendering. Keep native handles, selection geometry, and existing bridge lifecycle. Do not alter shared embedded assets, generated files, native private APIs, or add a custom selection layer. A rebuilt iOS binary is required; Metro reload alone cannot apply the Swift change.
- Isolate comment-quote decoration in a local component. Retain one SourceText with its two-line tail ellipsis and use its native onTextLayout measurements to position at most two independent underline views, with two points of clearance below each line box. Keep dashed comment-only and solid stroke decoration, reserve the final line's clearance, exclude decoration from touch/accessibility, and reset measurements when the quote text changes. This removes reliance on the font's baseline-relative textDecorationLine position without splitting or duplicating accessible text.
- Use mobileColors.markStroke for the quote borders, matching the article's `--slax-mark-border-color` and PDF mark stroke (`#F6AF69`), instead of a popup-specific literal.
- The inline Overview prefix is a nested SourceText, whose base style overrides inherited typography. Apply the excerptText style explicitly to the prefix as well as its parent, preserving its muted color while matching the 14-point size, line height, and font scaling. The expanded Overview dialog is outside this typography refinement.

## Risks / Trade-offs

- Outside-tap handling can swallow checkbox taps or text-selection gestures → verify first-tap toggling, editor focus/selection, background taps, drag dismissal, and native Back on iOS and Android.
- Moving the action into navigation can leave stale enabled/loading state → exercise empty, whitespace, one-character, cleared, pending, failure, and ownership-invalid states through the rendered header.
- Long email/localized copy can wrap → retain flexible row text and scrollability; exercise Chinese/English and small-device keyboard layouts under both system appearances.
- Long drafts can expand intrinsic input height → constrain the form to the viewport and let the editor flex and internally scroll; verify short/long drafts against actual production styles with the already-installed Yoga engine at closed, open, and restored keyboard heights.
- The earlier diagnostic change remains unarchived → keep this delta limited to feedback presentation and explicitly retain its attachment rules; reconcile the superseded separate-dismiss/cancel wording when sequencing archive work.
