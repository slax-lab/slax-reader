## What Changes

- Remove the unshipped vector run/queue/ledger/lease framework and its source/daily contracts, routes, configuration, tests and migrations. Preserve unrelated baseline behavior and useful generic tooling fixes. Add no PostgreSQL tables, columns, migrations or triggers, and no Durable Object locks or coordination service.
- Use exactly `VECTOR_V5_ARTICLE`, `VECTOR_V5_USER` and `VECTOR_V5_COLLECTION`, plus `VECTOR_V5_MAINTENANCE_WORKFLOW`. Normal `pnpm api -- dev` reads ordinary native configuration; no test overlay, guessed account, implicit fallback or recipe/shard/frozen switch is required. AI owns all Vectorize bindings; Core and Edge use existing VECTOR RPC.
- Store article representatives as `a:<userId>:<bookmarkId>` and chunks as `a:<userId>:<bookmarkId>:c:<n>` in the article default namespace. Mandatory numeric `user_id` metadata scopes private vector queries. Remove article/chunk `recommendable`; neither a save nor published Collection membership admits an article to a public pool. A physically existing article metadata index remains unused, with no production cleanup.
- Reuse one minimal maintenance service for article writes, existing owner-member Collection aggregation and two separate user preferences. Recompute from current business rows and existing originals rather than maintaining vector state in PostgreSQL. Native Workflow steps own heavy work; existing mutation hooks request maintenance.
- Keep saved-article and subscribed-Collection user profiles separate in both IDs and `user-article` / `user-collection` namespaces. Empty profiles are explicit, not zero-vector success. Collection `recommendable` visibility is unchanged.
- Add one normally authenticated `POST /v1/search` with independent titles/fulltext/article_vector/collection_vector channels, immediate admitted SSE partials, channel_error outcomes and one final complete result/status snapshot. Share one raw V5 matching query embedding across the vector branches; title/fulltext are independent.
- Search authorized Collection article/subject titles and the user's RSS feed/entry titles under the existing RSS lab/subscription gate; fulltext searches own saves and actively followed readable Collection members. Vector recall uses own article representatives and readable published Collection aggregates, including owned/followed Collections without recommendation exclusions. No RSS body/vector query or source re-embedding/write is added.
- Fuse by standard unweighted one-based RRF with k=60, typed stored-entity dedup and authorized navigation origins; never collapse private snapshots by URL or combine incompatible raw scores/preference weights. Bound D1/PostgreSQL candidate paging, expose incomplete coverage and revalidate final permissions. Preserve resources through streaming completion/cancellation using the existing ContextManager cleanup mechanism, with minimal deferral and no new DI graph or auth changes.
- Preserve `/v1/bookmark/search` on jina-clip-v2, old buckets and its existing all-tags/response contract. The new interface has no tag filter in its first contract. This is approved additive natural-query search, not a legacy query/index cutover or Collection recommendation alias; its tasks remain unchecked pending implementation and runtime evidence.
- Return `no_public_candidates` from the article feed until an operator-supplied pool exists under a separately established contract, without ANN, latest/popular queries, candidate hydration or model calls. Retain article ranking algorithms in `design.md` section 6 as paused historical design. Existing Collection recommendation and preference materialization remain; no pool endpoint/script is added. Bulk synchronization and its auth contract have a separate nonoverlapping delta in `vector-bulk-sync`.

## Capabilities

### New Capabilities

- `vector-v5-runtime`: Fixed-binding private article identities, metadata isolation, minimal shared processing and the approved one-route hybrid SSE search contract in its existing delta.
- `preference-maintenance`: Current-state Collection aggregation and independent exact-user preference materialization without new persistence.
- `content-recommendation`: Retained Collection recommendation with existing visibility rules and an explicitly empty article feed pending a separately supplied public pool; this is not the new query-driven search.

### Modified Capabilities

None. Existing `bookmark-vector-indexing` and `owned-bookmark-search-filtering` keep the legacy jina-clip-v2 endpoint, buckets, all-tags and final-admission guarantees unchanged. The new POST /v1/search is explicitly authorized within vector-v5-runtime, has no tag filter in this first contract and is not a cutover of the old route. No new search capability file, source/daily capability or overlapping bulk delta is introduced.
