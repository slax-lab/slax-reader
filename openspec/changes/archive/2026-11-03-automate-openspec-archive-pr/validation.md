## Compiler security review

The new workflow reuses the repository's existing `DEEPSEEK_API_KEY`; it introduces no new secret value and no new third-party action beyond the pinned gh-aw and standard action set already used by the repository. The compiler's safe-update warning names only `DEEPSEEK_API_KEY` as a newly restricted secret reference for this workflow. Its standard gh-aw token wiring is unchanged. No PAT, empty-commit credential, or additional repository secret is required.

The DeepSeek key is supplied to the same engine configuration already used by PR review. Network access is limited to gh-aw defaults, `api.deepseek.com`, and `registry.npmjs.org`; the pinned OpenSpec package already used by this repository is fetched through npm. No credential value is printed or added to an artifact. Agent permissions are read-only. The explicit checkout sets `persist-credentials: false`; gh-aw subsequently configures its standard job `GITHUB_TOKEN`, which remains read-only in the agent job. The only enabled external writes are one comment and one documentation PR through Safe Outputs, with `slax-lab/reader-core` as reviewer. Merge, approval, direct-push, review-submission, issue-creation, issue fallback, and direct Feishu outputs are not enabled.

## Local review

- **Bugs:** the automated PR review found that gh-aw's default PR checkout evaluated the closed task branch. The first correction used the source PR's merge commit; independent review then found that this could still be a historical snapshot when later task PRs had merged. The current revision disables the default PR checkout and explicitly checks out current `dev` for both automatic and replay runs. A compiled-lock test verifies the ref, checkout order, credential setting, and absence of `Checkout PR branch`. A later automated review found that the default token could leave the archive PR without automatic review and readiness. The empty-commit alternative had one-commit and non-fatal trigger limits; the direct-PAT alternative exposed its write token to the agent job. The accepted final design deliberately retains the default token and has the task PR author comment `/review` on the archive PR. That existing `issue_comment` path starts **PR Review (on demand)** and the same `workflow_run` gate without relying on an automatic PR workflow. The source-PR cross-link and team review request make the archive PR visible first. Native `queue: max` retains pending evaluations instead of silently replacing them. The archive prompt now uses the pinned validation command and stages the result before `git diff --cached --check`, so new archive files are included.
- **Security:** the trigger is merged-only and same-repository, the agent token is read-only, the custom checkout does not persist its checkout credential, publication uses Safe Outputs with the default `GITHUB_TOKEN`, no automatic merge or approval exists, and the notification path is unchanged. No additional credential or agent-accessible write token exists. The on-demand review command and archive merge remain human actions.
- **Compliance:** the implementation was checked against the proposal and `openspec-change-archiving` delta. Rulesync and gh-aw outputs were regenerated through their owners. The archive suite runs through the existing Tooling CI command, the OpenSpec commands are pinned, task classification and same-capability ordering remain mandatory, and live rollout observations remain pending rather than being claimed by local checks. `docs/CI.md` retains the operational procedure after this change is archived. Review outcomes are recorded after their respective rounds rather than asserted in advance.
