## Context

The Extension background accesses Web PowerSync through the existing offscreen iframe and `/x/ext-bridge`. Bookmark status, PDF publication metadata and subscription unread inputs already exist in SQLite.

## Decisions

- WXT supplies the default popup for supported browsers. The background disables the action popup while signed out so a toolbar click or Alt+Y can open or focus the existing sign-in page. The popup checks the session when it first opens to cover a stale browser action setting. Save delegates to the current collector, and the context menu retains its save action.
- Save, Inbox, and notification clicks check the current session even in a popup opened in an earlier session. Interactive authorization failures use the existing sign-in tab handler. A background authorization failure clears the session and toolbar state without opening a tab. The interactive subscription failure passes the rejected token to the existing session guard.
- Toolbar saves for HTML pages share the existing content-script submission and use its server acknowledgement in the toolbar popup. A transient receipt scoped to the tab, URL, and account covers reopening before the bookmark is observed in local sync. The popup follows the existing bookmark lookup when the notification watch refreshes. During submission, the primary slot shows muted text and matching loading dots directly on the paper surface. After acknowledgement, the saved label and completion icon use the primary accent on the paper surface. The filled action returns with the synced bookmark UUID when the reader is available. PDF collection and recovery use their dedicated surfaces.
- The bridge reads current SQLite results and signals changes to a single Extension background listener. The background shares the same result with the toolbar icon and open popup ports, and owns account checks and serial local reminder writes. A small coral notification dot with a dark warm outline sits at the upper-right edge of the Extension icon, clear of the existing saved-page badge. No notification history or polling is required.
- Store the Inbox checkpoint, observed processing IDs and dismissed IDs by Web environment and account. A readable, undismissed bookmark qualifies if created after the checkpoint or retained as processing. The first usable snapshot seeds the checkpoint. Its time is anchored to the start of notification monitoring so a save started before the first sync can still remind. Clearing uses a local checkpoint captured when the main Inbox actually displays. A later upload or rewritten timestamp cannot recreate a dismissed reminder for the same UUID.
- Collection unread uses the existing list SQL and timestamp comparison. Clicking advances the cursor through the displayed entry and navigates after the local write. Existing upload persists the cursor monotonically.
- Return up to two candidates per kind from SQLite, with one save candidate sufficient when subscriptions are unread. The background selects one of each kind when both are present, with subscriptions first, or up to two from the available kind.
- Put the emphasized quoted collection name or bookmark title, its muted status, and a coral trailing dot on a single clickable row. Measure the localized text at the actual row width and truncate the subject in the middle. Keep the full sentence available to assistive technology. The icon tile represents the source or event: a person with a heart for a followed collection, and a bookmark for a completed save.
- The popup fills the browser-native action surface and its footer with an Extension-owned warm-paper color matching the Web Inbox in light mode (`#FAF8F2`). The filled Save action is at the top. A compact bell and localized section label sit together above a lightly outlined notification card, with more space above the heading than below it. The card begins with its first notification. The divider between two rows aligns with their text column, and its spacing above and below matches the card's four CSS pixel padding. The secondary Inbox action fills the full-width footer, with its icon, label, and arrow centered as one group and its focus outline inset. The Save action and card sit 16 CSS pixels from the popup sides.
- On the two forward save transitions, the primary content fades out for 100 ms and the next state fades in for 150 ms, including the reader action fill. The control retains its height and its accessible label updates with the underlying state. Reduced motion skips the fade.

## Trade-offs

The browser only knows what has reached its local database. A late-sync older save may be absent from the Inbox checkpoint, and a repeated save that retains the same UUID does not get a separate reminder. A first-time unavailable or unauthenticated bridge has a distinct state from an empty result.
