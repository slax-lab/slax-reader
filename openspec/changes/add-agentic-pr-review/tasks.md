## 8. Follow-ups found while operating the review

- [x] 8.1 Stop the review agent from reaching for GitHub over the network (found in the review of #24, whose published body carried a "Firewall blocked 1 domain: `api.github.com`" warning): the agent had run `curl https://api.github.com/repos/…/actions/runs?per_page=2` to check the routing claim beside it, and the AWF firewall denied the request by design. Fixed by adding the `actions` toolset to `tools.github` — the read the agent wanted now exists as a tool — plus a prompt section stating that the sandbox has no GitHub network route, so `gh`, `curl` and `git fetch` cannot work. Verified with an accidental A/B: #28's own reviews (which change `.github/workflows/**`, so they are exactly the CI-touching case) carry no firewall warning with the fix in the run, while probe #29, whose run used `main`'s config, still carries "Firewall blocked 1 domain". The review of #28 also caught a second-order defect in the same task's prompt text — the first version of step 1 replaced one dead end (`git diff` against a base branch that need not exist) with a worse one (`git diff HEAD^`, which is the pull request's previous commit because gh-aw checks out the head branch, not the merge commit), so the wording now names the GitHub tools as the reliable source and requires an explicitly resolved range, checked against the tools' file list, with an instruction to report a partial diff rather than silently review one. Rounds 3 and 4 then disagreed with each other about which commit the worktree holds on the automatic path (round 3 argued the merge commit from the plain `actions/checkout` step; round 4 cited `checkout_pr_branch.cjs`, which checks out the head branch for both paths, and showed the range `git merge-base origin/main HEAD..HEAD` matching the tools' file list). Rather than pick a side, step 1 now asserts **no** topology at all: the GitHub tools are the source of the diff, a git range must be resolved explicitly and checked against the tools' file list, and a partial diff must be reported instead of reviewed. Round 5 then showed that even the "base restore" half was path-dependent, so the prompt now asserts **no per-path outcome** — it still states the mechanism that makes the outcomes differ (the snapshot comes from `github.ref`), which is what the review of #35 pointed out when this line first claimed "no environment fact at all": the framework's snapshot of `.github/`, `.agents/` and `AGENTS.md` is taken from `github.ref`, which is `refs/pull/N/merge` on `pull_request` runs and the default branch on `/review` runs — so the restored copy holds the pull request's own version of the files it changes in the first case and the merged version in the second. What the prompt says instead is a directive: read the diff and the files through the tools, resolve any git range explicitly, check it against the tools' file list, and never review a partial or stale version silently.
