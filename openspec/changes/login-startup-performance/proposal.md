# Proposal

## Why

Anonymous Web visitors see the background while login waits for several rounds of client resources. Recorded direct login spent 823 ms resolving its route and dependencies and another 571 ms on the default layout and its dependencies. Entering the root URL also resolved the Inbox before the authentication redirect.

## What Changes

- Let login render through the shared shell without waiting for the default layout or its promotion host. Preload the login route's static resources from the login document and load the invitation banner and in-app browser hint when applicable.
- Resolve a small Inbox route module before authentication. Load the Inbox view after the route is admitted while preserving the root alias and campaign URL.
- Start loading the two supported locale resources from the root and login documents, using the paths generated by the i18n build. Keep locale selection with i18n.
- Evaluate the PowerSync dependency boundary separately against the current public-page-startup contract.

## Capabilities

### New Capabilities

- `web-login-resource-loading` covers resource discovery for the Web login and Inbox entry routes.

### Modified Capabilities

None. The in-flight public-page-startup and KOC promotion continuity specifications remain constraints.

## Impact

The Web Nuxt app, generated locale resources, and the Inbox integration test import. The change requires no backend or schema work.

## Review

The user reviewed the ordered approach in the November 10 login timing discussion and requested implementation. The root entry retains the canonical Inbox URL required by KOC continuity.
