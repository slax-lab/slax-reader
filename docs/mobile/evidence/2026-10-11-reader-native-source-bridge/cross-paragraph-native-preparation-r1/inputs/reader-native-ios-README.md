# Controlled iOS Reader native input

The independent `control/ReaderNativeControl.xcodeproj` contains a small UIKit XCTest host and UI test target. It controls only the separately installed `app.slax.reader.uifixture` and asserts that the production `app.slax.reader` application remains closed. It has no production App Group, API or database access. Run only on an explicitly allocated Slax simulator with parallel testing disabled and one simulator destination; the project does not build or install the main application.

Prepare a fresh `reader-mixed` scope through `tooling/fixture-control.mjs` before each selected XCTest case. Record that scope's `render-context.json`, actual route, `reader-position.json` and `reader-lifecycle.json` before/after native input. The fixture controller prepares content and optional DOM selection; it never substitutes for a native Back tap or edge gesture. Refresh the current Reader screen/WebView in the isolated JS snapshot before execution.

Start with `testInspectPreparedReader` and inspect its native accessibility tree and frame. The Back selector accepts only the known platform labels inside a native navigation bar and rejects missing or unknown controls. It does not assume that the accessibility tree has exactly one WebView. The only automatic system-alert action is Cancel for the previously observed Open-in-Slax-Reader title and two-button Open/Cancel pair; all other overlays fail the test.

The remaining cases perform an actual native Back tap, a slow eight-percent edge drag intended to cancel, a ninety-percent edge drag intended to commit, and a native Back tap with a separately prepared selection. Route observations and actual page IDs determine the result: a canceled gesture must retain the same ready page without disposal, while committed exit must return to Library and finish its position writer and native detach command. A prepared selection tests only its dismissal; it does not prove native selection creation.

`testNativeLongPressOriginalBodyWord` is a separate genuine-input probe. It accepts only the unique visible `Alpha` native text element from the inspected mixed article, checks that its actual frame is below the native Back region, and presses it for one second. It retains the native tree and frame before and after input and requires one hittable element with the exact `selection_action_bar` identifier, regardless of its accessibility element type. It does not create a DOM range, publish a bridge event, dismiss an unknown menu, or choose a replacement word. The probe and matcher compiled in the bounded ARM64 helper build recorded in [build preparation](../../../../docs/mobile/evidence/2026-10-11-target-ios-reader-native-longpress/build-preparation.json). The [completed aw4 native Alpha run](../../../../docs/mobile/evidence/2026-10-11-reader-native-source-bridge/aw4-native-alpha/report.json) observed five source characters, blue handles and the application menu after this genuine input. A separate [completed native Back run](../../../../docs/mobile/evidence/2026-10-11-reader-native-source-bridge/aw4-native-selection-back/report.json) dismissed that same live native selection while retaining Reader. These scoped results do not establish cross-paragraph selection or whole Reader parity. Historical failures and their earlier driver source remain unchanged.

The independent [cross-paragraph preparation](control/cross-paragraph/README.md) leaves this compiled driver/project unchanged. Its new source identifies the actual end handle from a native screenshot and plans one native drag into the inspected second paragraph. It is uncompiled and unexecuted; its offline snapshot guards and archived-frame analysis are not native acceptance.

Lifecycle records are enabled only by `__DEV__` plus the controlled fixture scope. They contain page IDs, tags, readiness, observed position and completion phases, without article content or session credentials. `native-detach-completed` records completion of the real adapter command; it is not a claim about unrelated resource ownership or network cancellation. Actual native execution and comparison remain pending until a per-case device report is saved.
