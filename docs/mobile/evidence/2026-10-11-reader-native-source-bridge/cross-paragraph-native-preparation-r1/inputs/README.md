# Prepared native cross-paragraph input

This directory is a new, uncompiled XCTest source and a readonly snapshot guard. It does not change the already compiled `ReaderNativeControl.swift` or its project, the unique target UI app, the original source application, Metro, or any device. A future helper build must declare its own closed project membership, copied source hashes, unique empty host identity, compiler result, XCTest Mach-O and `.xctestrun` receipt. The existing helper Mach-O is not evidence for this new source.

The input reference is the completed [aw4 Alpha native test](../../../../../../docs/mobile/evidence/2026-10-11-reader-native-source-bridge/aw4-native-alpha/report.json). Its actual native PNG shows the blue start/end handles; its native accessibility tree exposes `Alpha` at `{20,326,46,20}`, the second paragraph text at `{75,378,164,20}`, and one hittable `selection_action_bar`, but no separate handle identifier. The native image is 1206 × 2622 pixels for a 402 × 874 point viewport. The right handle's observed solid-blue component is `{162,978,48,106}` pixels, with a ball center `{186,1059.5}` pixels (`{62,353.1667}` native points). These are observed input references, not visual-parity tolerances.

Before this continuation, the external executor must bind a newly completed genuine one-second `Alpha` native press to its fresh current fixture scope and immutable five-character/one-path readonly snapshot. `bindGenuineAlphaContinuation` rejects mismatched device, scope, source/stage/app/helper hashes, incomplete results, synthetic selection or repeated input. It still requires independent verification of the report's raw artifacts and a current live-state observation. Historical aw4 selection is an input reference, not a new live selection. The new driver rejects a missing menu, different viewport/body metrics, unknown overlays or another running main app. It examines that same actual native screenshot inside a small region around the live word frame, requires two unambiguous blue handle components, and identifies the lower right ball. It performs exactly one slow native drag from this detected ball to a point inside the actual second-paragraph text frame. A missing or changed handle/frame stops before the drag. It never long-presses again, creates a DOM Range, invokes a selection preparation action, taps an annotation/menu action or chooses a replacement word.

A passing native test alone establishes input delivery and a retained menu. After the test, the existing **readonly** `inspect-selection` action must produce a separately copied snapshot. `snapshot-guard.mjs` checks the same cache/page/native tag, settled source and application selection, retained actual 240-pixel position, multiple source paths and range bounds that reach the second paragraph's actual native frame. Multiple first-paragraph nodes and a retained five-character Alpha selection both fail. Exact copied text, persisted highlight/comment content and cross-paragraph menus after further scrolling require separate native evidence.

The Node guard regressions use the archived genuine Alpha snapshot and constructed after-state objects solely to test refusal/admission logic. They preserve the source distinction between `window.Selection.toString()` paragraph separators and captured `select_content` joined text. They do not inject these objects into a document or establish native cross-paragraph acceptance. Run them with `node --test apps/mobile/fixtures/reader-native-ios/control/cross-paragraph/snapshot-guard.test.mjs`. `reference-analysis.py` reads only the hash-bound archived PNG/AX/snapshot and records its blue components. Swift pixel orientation, native drag delivery and after-state acceptance remain uncompiled and unexecuted.

Any future execution requires an explicit Root allocation, a fresh scope without prepared selection, current app/stage/native/source provenance, and independent resource/device guards. The completed aw4 Alpha and selection-Back reports remain distinct historical evidence; a current TypeScript refresh requires new ancestry.
