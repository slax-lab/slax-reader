# Mobile architecture

The application uses an application-owned Expo workspace and the public `packages/contracts` boundary. It imports no implementation from Web, Extension, or API. Metro uses Expo's pnpm-aware monorepo resolver; native dependencies use Expo autolinking and the local `modules` directory.

`MobileProvider` constructs one data runtime, migrates preferences before choosing the API environment, and starts storage before mounting authenticated screens. `SessionController` serializes startup, token-matched invalidation, account replacement, and logout. Account-specific observers mount after the selected owner is ready. API requests use the source contract, cancellable fetch, response/error mapping, and source platform/version headers. Debug environment changes take effect after restart; sync credentials also carry their API origin.

The approved native stack owns all nine source routes. Reader business actions and overlays are TypeScript. The rich document remains the pinned source HTML/CSS/JavaScript with a typed request/page bridge. Native reader views supply cached scheme interception, selection-menu suppression, touch coordinates, iOS scroll/inset controls, and page disposal. Local view/module code fills native gaps without editing installed package sources.

Android enables the system back callback API. React Native 0.86.3 registers its AndroidX bridge only when both the device and target SDK are at least 36. On Android 13–15, the application-owned `with-native-back.cjs` plugin adds a lifecycle-bound callback that forwards committed system back to the existing React Native navigation handler. It disables that callback while invoking the root activity fallback, preventing recursive dispatch when the JavaScript stack cannot go back. Android 16 uses React Native's existing bridge. This follows Android's [supported back-callback migration](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture); native system-back, modal priority and root background/resume results remain separate from plugin-generation checks.

The actual API 34 native-input batch closes the Settings language dialog before popping Settings, About and Reader to Library, then backgrounds the root activity. A separate MAIN-launcher resume retains the exact fixture scope and complete observed navigation state. The historical batch's dev-client VIEW reentry is explicitly excluded from retained-activity verification. These results do not establish predictive gesture progress, other Android API levels, Reader background persistence or complete visual parity.

`SlaxLegacy` locates the original database/cache/preferences, provides cross-process preference compare-and-swap and exclusive data ownership, and reads legacy DataStore protobufs. Upgrade adoption requires explicit verification and read-only structure/data/queue snapshots around initialization. A failed verification keeps original files and pending work. The development fixture entry is separately gated and cannot authorize production adoption. See the compatibility report for the exact verification achieved and outstanding device runs.

PowerSync owns local synchronized rows, hidden local-bookmark JSON, transactions, and retryable upload queues. Upload batching retains source order and transaction boundaries. File caches retain the original owner-aware paths. Cache cleanup removes only source-selected cache fields/files and keeps unrelated metadata and business mutations.

Each authenticated account creates fresh, revocable database, preference, file-cache, and native-reader scopes. Native readers capture an immutable owner identifier; their document/resource access must match the current native owner. Logout resets that owner, closes existing streams, cancels automatic caching, joins its work, and clears data before another account can render. Delayed React mounts and asynchronous cache results cannot acquire the next account's scope.

`BackgroundArticleCache` watches personal inbox candidates, subscribed collection candidates, local cache metadata, and cache preferences. It retains the source default of 50 automatic articles, supports unlimited caching, excludes completed manual caches from the limit, and applies collection limits per owner. The two domains each run at most three article downloads with a queue of 100. Image downloads follow the image preference and retain usable HTML when individual images fail. Foreground reads reserve their cache against scheduling and eviction while existing downloads can finish. Eviction rechecks manual ownership, preserves unrelated JSON for active personal rows, and leaves synchronized business operations untouched.

The independent iOS share extension and Android incoming-share activity can collect without a running JavaScript application. They share authentication/environment preferences through the native store and preserve the source identities and UI. Outbound article sharing uses title/text/URL with iOS link/image metadata.

On iOS, a runtime-owned StoreKit wrapper listens beyond the subscription page, remembers purchase ownership before starting payment, verifies signed transactions against the backend, and finishes verified transactions only while the owning account remains current. Purchase, restore, startup and native event queues capture their session epoch before asynchronous work; preference CAS, backend validation, native calls and entitlement/state updates recheck it. Expired work preserves its unfinished transaction and saved order without publishing errors or success into a fresh login, including a same-user login with an identical token. A known order owned by another account is rejected before backend verification; legacy restored orders without local ownership retain the source backend validation path. A native finish already invoked while its account is current cannot be undone, but subsequent local deletion/state publication still cancels after a scope change. The subscription WebView uses the source cookie/bridge relationship and page-level purchase lock. Android retains the source web subscription behavior. Signing, sandbox payments, revoked entitlements, and reporting delivery need controlled native verification.

Telemetry has two best-effort collectors: the existing first-party `/events` protocol and approved Firebase SDKs. The device analytics identifier migrates with persistent runtime preferences, native screen auto-reporting is disabled, and source screen/action names are sent explicitly. First-party events capture their session before asynchronous identifier lookup and reject a departed session before sending. API credential reads, retries, synchronization credential writes, and chained RSS operations also retain their initiating session scope; delayed work cannot acquire a later login's credentials or publish its saved bookmark into another feed. Collector failures are isolated from application actions. No SDK or test log should expose authentication or purchase credentials.

Mobile's design profile, source tokens, assets, locales, and test identifiers are application-owned. Matched Chinese/English platform renders and actual native interactions remain acceptance requirements.


## Library presentation and search

The authenticated Library retains a complete ordered local list for the active Inbox, Starred, Archived or Collection source. It has no data pagination. `LibraryRepository` projects only row identity, title/alias, URL, processing and action states; full metadata remains in detail/search repositories. A separate projected download-state subscription merges by saved ID and preserves unchanged row references. Account-owned snapshots survive route focus changes and are revoked by the database lease. PowerSync table invalidation can still rerun SQL; reduced JS publication is not a claim of row-granular SQL invalidation.

After verified admission, the Library publishes its first local state and calls the runtime's presentation milestone. Sync connection and automatic resource warmup begin after this milestone, while local identity and credential refresh remain separate. Recovery and first-adoption ownership checks remain required.

The Search route is opened beside the add action. Typed keywords search local title/alias, description/summary, URL and source metadata across nondeleted personal lists, accessible Collections and synchronized RSS entries. Search-result batches are separate from the unpaginated homepage. Personal tags use stable UUIDs and AND intersection. Selected tags restrict articles to owned saves; Collection/RSS sources have no personal tag relation. RSS results respect Labs availability. Exact typed `#tag` tokens become chips when committed; unresolved tags block cloud submission. Native keyboard Search and the submit button share one command.

Cloud enrichment runs only on explicit nonempty keyword submission, sends `tag_uuids`, and preserves local results on failure. Query/account replacement cancels or discards previous work. Saved UUIDs merge personal hits in place; cloud-only hits append in API order. Verified saved relations can collapse matching RSS/Collection entries, but URL strings do not merge arbitrary permission contexts. The Reader can fetch admitted personal metadata for a saved UUID not yet present in the local sync window without inserting a fabricated sync row.

Self/Collection avatar bytes have a separate account+origin-scoped resource role using the existing native atomic image store. The manifest has a 24-hour soft refresh interval and 20MiB LRU budget with a 1MiB per-image bound. Existing bytes render before revalidation; failed refresh retains a valid same-owner image. Account revocation cancels pending work; image-cache cleanup invalidates cached display identities. Expo Image provides in-memory display over the app-owned local URI.

The drawer holds an input lock from recognized opening gesture through completed dismissal, including reversal and cancellation. Descendant pointer/accessibility input is hidden while active; row callbacks recheck the UI-runtime lock and list native gestures wait for the drawer gesture to fail. The Library stops existing scroll momentum at the phase boundary.

Automatic PDF fills group contiguous missing blocks into acquisitions of at most 1MiB, preserving 256KiB cache blocks. Foreground requests promote covering queued/in-flight acquisitions; cached blocks are skipped. A server returning the entire document is coalesced through the existing single-stream fallback. Range status/bounds/length, optional ETag and final complete-file SHA checks remain required. Automatic fills start from the active Library under the existing count/retention policy, without a PDF-specific download button or promise of OS-suspended transfers.
