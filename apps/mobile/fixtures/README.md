# Mobile acceptance fixtures

These 29 synthetic scenarios and eight HTML documents are shared inputs for the source Android/iOS app and the migrated Expo app. They contain no real account data or usable credentials. Every application/API/artwork hostname uses `.test`, except the deliberately inert YouTube player fixture. A native capture adapter must supply player events locally and must block external network access.

`scenarios.json` holds complete settings, session placeholders, database rows, local JSON rows, article cache inputs, PowerSync/network state, API responses, and scripted interactions. `manifest.json` pins the input bytes. Reproduce the bundle with `python3 apps/mobile/fixtures/generate-fixtures.py` from the repository root. Verify it with `node apps/mobile/fixtures/verify-fixtures.mjs`.

The API transport in `transport.ts` only accepts a synthetic HTTPS `.test` origin and fails when a route is absent. It never invokes real fetch. More-specific request-body/query routes win, while the first equal-priority route supplies an intentional error override. History retrieval remains an explicit `fetch_history=1` request; cached-page responses support the expanded-window reload used by the source RSS model. Overview deltas and growing full-outline values have deterministic delayed NDJSON chunks, including intermediate capture checkpoints and cancellation; adapters must consume those same chunks rather than flattening the response.

The Expo adapter in `FixtureApp.tsx` uses the production `ApplicationRoutes`, screens, components, repositories, and PowerSync schema. Before mounting it creates and re-reads the controlled marker in a new cache `slax-ui-fixtures/<run>` directory. Its database/cache live only in that directory, authentication/preferences live only in memory, the sync connector is absent, and all API requests use the strict prepared transport. It never constructs the production data runtime, native preference store, or native login/purchase provider. The context's explicit development guard and directory check prevent this provider from becoming a production seeding shortcut. Native execution and visual acceptance remain unverified.

Create a fresh, separate native fixture project through the repository entry point:

```sh
pnpm mobile -- fixture:project --scenario library-populated --locale en --platform all
pnpm mobile -- fixture:project --project /absolute/generated/project --commands
```

The generator copies allowed public mobile sources/resources into a new marked directory directly under the system temporary directory and links the existing dependencies. It regenerates native projects with separate application identities and a separate development-client scheme, disables automatic Firebase collection, and omits the production App Group and inbound share target. It does not copy the original native projects, `.env`, operator configuration, databases, or credentials. Run Metro on the generated command's independent port 8083, build/install that isolated project, then use its explicit development-client URL. Creating/prebuilding this project validates native configuration; it does not render or verify the UI. Generate a fresh project after changing native inputs. When reusing a compiled native target for JavaScript/test-assets-only updates, first preserve the native artifact and record an explicit new immutable input revision with all changed-file hashes. Verify that native Android inputs are unchanged; iOS-only native/plugin changes require an iOS rebuild. The temporary project watches only its linked dependency store, and the printed Metro command sets `EXPO_NO_METRO_LAZY=1` so asynchronous dependencies outside the temporary project resolve in the eager development bundle.

The development-only `globalThis.__SLAX_UI_FIXTURE__` exposes the scenario/input digest/scope, controlled `setSync`, `setNetwork`, and `setLocale`, and `perform(actionIndex | action)` for prepared state transitions. `selectCase` creates a fresh runtime and immediately unmounts previous routes, including retained sheets. `captureContext` records the actual current route, readonly root navigation state/`canGoBack`, and committed cache/image/language preference values, alongside native measurements. This bounded preference observation excludes authentication and secret values. Mounted production screens subscribe only while the controlled fixture provider is active. List/source/history/menu, login agreements and synthetic provider outcomes, feedback, deletion notice, and supported reader commands use their production callbacks or actual DOM/native bridge. Unsupported actions fail explicitly. The nonvisual measurement component records actual native window/screen dimensions, device scale, font scale, safe areas and system appearance in `render-context.json`. Android model and OS version come from React Native native constants; iOS model must be obtained from the capture host. Displayed clock remains pending until the native frame is inspected, separately from the sampled capture time. Each accepted action is recorded as `nativeInteractionVerified: false`; programmatic preparation cannot prove touch/keyboard/accessibility/hardware-back acceptance. Real native selection coordinates, player events, cancelled interactive pop, background/resume, and purchase/login surfaces still need device action drivers. Live YouTube is blocked and has no prepared local player provider.

After the separate fixture app has actually attached to Metro, `node apps/mobile/tooling/fixture-control.mjs --platform android --device 'sdk_gphone64_arm64 - 14 - API 34' --case settings --locale en --font-scale 1` selects a closed case and returns its fresh scoped context. `--observe current` only reads the current route/stack. The controller refuses a different app, device, ambiguous inspector target, or external control endpoint. The transport uses the installed React Native abort-controller semantics and attaches prepared chunk streams explicitly because its Response polyfill does not accept a ReadableStream constructor body. Timed chunks and cancellation are checked through the actual application API parser; this is host compatibility evidence, separate from a native streaming frame.

`tooling/fixture-android-batch.py --device emulator-5560 --output <fresh-owned-absolute-directory> --mode initial|navigation|header-navigation|native-controls|native-delete-controls` freezes its executed driver, saves native PNG/hierarchy/context and logs actual input. The device must be the allocated `slax-migration-controlled` AVD. Native actions target unique enabled controls at measured bounds, and after-state guards reject a different foreground app or retained error overlay. Navigation batches preserve MP4 and failed inputs even when the after-state guard fails. These outputs are candidates until their state and conditions are inspected; route preparation does not establish UI parity. `tooling/fixture-source-android-batch.py` runs the same declared initial cases through the original isolated Compose instrumentation with `fixtureInitialOnly=true`, recording unsupported routes explicitly.

Controlled host commands can select another prepared case on the same fixture build or prepare one of its actions:

```sh
adb -s "$SLAX_FIXTURE_DEVICE" shell am start -a android.intent.action.VIEW \
  -d 'slaxreader-ui-fixture://control?case=login-agreements&locale=en' \
  -p com.slax.reader.uifixture
adb -s "$SLAX_FIXTURE_DEVICE" shell am start -a android.intent.action.VIEW \
  -d 'slaxreader-ui-fixture://control?index=0' -p com.slax.reader.uifixture
```

`index` addresses the currently selected scenario's planned actions. `action` can instead contain one URL-encoded JSON fixture action. Production schemes, unknown cases/locales, filesystem paths, unrecognized parameters, and executable JavaScript are rejected. These commands prepare state; real native taps, keyboard, gestures and back require separate input evidence.
