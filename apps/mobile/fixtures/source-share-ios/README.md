# Original Swift Share UI fixture

This standalone simulator host and Share extension compile the unchanged, checksum-pinned original `iosApp/share/ShareViewController.swift`. The explicit Swift `ComposeApp.ShareKt` boundary returns deterministic synthetic results and the original fixed English labels. It does not execute original Kotlin, API, authentication, metrics, Firebase, App Group or production sharing logic.

The host identity is `app.slax.reader.sourcesharefixture`; the extension is `app.slax.reader.sourcesharefixture.share`. There are no production identities, App Group entitlements or external requests. The three exact `https://source-share.test/` URLs select loading, success or the generic source error message. The loading wait is bounded to sixty seconds. Original UIKit presentation, the 180-point container, typography, spinner, success symbol, animations and dismissal code remain unchanged.

Preparation verifies the closed source manifest and copies only its approved Share controller. The generated isolated Xcode project uses public Apple SDK frameworks and the local UI-only stub. Build with one job, simulator-only, without operator signing inputs. Device installation and native input require a separately allocated controlled simulator window.

Run `prepare-source-share-ios.py --source <pinned-original-checkout> --output /tmp/slax-source-share-fixture-<run>`, then `node source-share-ios/build-app.mjs --project /tmp/slax-source-share-fixture-<run>`. The packaging driver checks every prepared input digest, builds only the simulator scheme with one job, signs only the fixture bundles with public ad hoc signatures, and records binary hashes. It never installs an app or accesses a simulator.

The separate `control/SourceShareControl.xcodeproj` contains bounded XCTest cases for loading, success and generic error presentation. They tap the host's declared Share button and only its observed unique `Source Share UI Fixture` system activity, reject unexpected alerts, and retain actual native frames and accessibility trees. The system uses the host's display name for that row, despite the extension's declared `Slax Source Share` display name. Loading and error panels close through their inspected native background. The tests must run on an explicitly allocated simulator with parallel testing disabled. The programmatic boundary result and actual native input are recorded separately; neither proves original Kotlin functionality.
