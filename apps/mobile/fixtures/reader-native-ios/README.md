# Controlled iOS Reader native input

The independent `control/ReaderNativeControl.xcodeproj` contains a small UIKit XCTest host and UI test target. It controls only the separately installed `app.slax.reader.uifixture` and asserts that the production `app.slax.reader` application remains closed. It has no production App Group, API or database access. Run only on an explicitly allocated Slax simulator with parallel testing disabled and one simulator destination; the project does not build or install the main application.

Prepare a fresh `reader-mixed` scope (or the Library scope listed below) through `tooling/fixture-control.mjs` before each selected XCTest case. Record that scope's `render-context.json`, actual route, `reader-position.json` and `reader-lifecycle.json` before/after native input. The fixture controller prepares content; only `testNativeBackClearsPreparedSelection` permits prepared DOM selection. It never substitutes for a native tap, drag, long press, or editor action. Refresh the current Reader screen/WebView in the isolated JS snapshot before execution.

Start with `testInspectPreparedReader` and inspect its native accessibility tree and frame. The Back selector accepts only the known platform labels inside a native navigation bar and rejects missing or unknown controls. It does not assume that the accessibility tree has exactly one WebView. The only automatic system-alert action is Cancel for the previously observed Open-in-Slax-Reader title and two-button Open/Cancel pair; all other overlays fail the test.

The remaining cases perform an actual native Back tap, a slow eight-percent edge drag intended to cancel, a ninety-percent edge drag intended to commit, and a native Back tap with a separately prepared selection. Route observations and actual page IDs determine the result: a canceled gesture must retain the same ready page without disposal, while committed exit must return to Library and finish its position writer and native detach command. A prepared selection tests only its dismissal; it does not prove native selection creation.

`testNativeLongPressOriginalBodyWord` accepts only the unique visible `Alpha` text inside `reader-document`, checks its actual frame is below native Back, and presses it for one second. It now requires the source `selection_action_bar` with its own Copy/Comment controls and checks for duplicate system edit actions. It never creates a DOM range, publishes a bridge event, dismisses an unknown menu, or chooses a replacement word. The earlier probe compiled in the historical build preparation; that build does not verify these additions. The aw4 native Alpha run observed five source characters, blue handles and the application menu. A separate native Back run dismissed that live selection while retaining Reader. Those scoped historical results do not establish duplicate-menu suppression, cross-paragraph selection, or current acceptance.

The independent [cross-paragraph preparation](control/cross-paragraph/README.md) uses its own driver/project. It identifies the actual end handle from a native screenshot and plans a drag into the inspected second paragraph. Its offline guards and archived-frame analysis are not native acceptance.

## Targeted user5 regression preparation

These additions are prepared only: no native build, installation, simulator start, or runtime pass is implied. Later execution requires a newly allocated, explicitly identified Slax simulator, the refreshed `.uifixture` build, English application labels and English or known Chinese system edit labels (system Copy accepts exact `Copy`, `复制`, and the natively observed iOS `zh-Hans-CN` label `拷贝`; the application Copy selector remains English), one destination, `-parallel-testing-enabled NO`, and exactly one `-only-testing:ReaderNativeControl/ReaderNativeControl/<test-name>` per fresh scope. The harness refuses to launch an unprepared/stopped fixture and retains `.keepAlways` screenshots, native trees, and JSON observations.

- `testNativeScrollThenBackground`: fresh `reader-mixed`, Alpha visible below Back, no selection. Performs a frame-derived document drag and requires actual Alpha displacement before Home.
- `testNativeLibraryBackgroundAndResume`: fresh `library-populated`, own Inbox, mixed-title row visible.
- `testNativeLibraryVerticalDrag`: own Inbox with the exact mixed-title and `Long article for scroll restoration` rows visible in one native scroll container. Requires sustained upward anchor displacement, not bounce. The six-row default inbox may fit entirely on larger devices; prepare an overflowing synthetic scope or an appropriate smaller viewport before running. Missing overflow is an explicit failed precondition, not a gesture pass.
- `testNativeLibraryRowSwipeReverseInterruptedThenVertical`: same overflowing Library scope. Opens and reverses the mixed-title row using its observed frame, performs a short swipe immediately followed by Home, resumes and closes any remaining offset, then proves vertical content movement. XCTest event quiescence may let settling finish before Home: this is a real lifecycle interruption, not proof of an in-flight recognizer/animation cancellation.
- `testNativeCachedArticleRoundTrips`: fresh cached `reader-mixed`, Alpha visible, no selection. Native Back then three actual Library-row/Reader/Back round trips; records completed count and per-trip tap-to-visible-Alpha and Back-to-Library seconds. These include XCTest overhead and are neither FPS nor Release profiling; no performance threshold is imposed. Preserve cache manifest and lifecycle/page IDs externally to distinguish cached readiness from fixture-network fallback.
- `testNativeLongPressOriginalBodyWord`: fresh `reader-mixed`, no prepared selection. Requires the source menu and at least two clean app/SpringBoard snapshot pairs spanning two seconds within a measured 15-second acquisition budget. Each observation obtains one immutable native snapshot per app and classifies its descendants locally, preserving ancestry and frames; only the unique English application Copy button and its contained text descendants are permitted. Native Menu/MenuItem nodes and unclassified edit labels fail immediately after capture, without dismissal. Capture latency, node trees, pair count and total observation time are attached. A synchronous XCTest snapshot cannot be forcibly interrupted; an over-budget return fails rather than being accepted as clean.
- `testNativeAlphaHighlightMenuState`: same fresh Reader. Native Alpha selection → application Highlight → menu disappears → native Alpha selection again must offer Remove; duplicate-system-menu checks surround the transition.
- `testNativeAlphaCommentEditorCopyPaste`: same fresh Reader. Native Alpha selection → application Comment → exact Alpha quote and selection-bar dismissal. Types one synthetic token, double-taps it, taps a uniquely distinguishable enabled system Copy, deletes the selected token, long-presses the empty editor, taps system Paste, and requires the token restored. Submits only to the synthetic fixture and requires exactly one corresponding comment row. The application's `Copy highlighted text` is not used as system Copy. An OS menu exposing no distinguishable Copy/Paste action fails explicitly; do not substitute clipboard APIs, keyboard shortcuts, or CDP selection.

Background cases observe application state with a bounded XCTest predicate for 30 seconds (40-second outer timeout), accept either running-background state, and record whether suspension actually occurred. They refuse to reactivate after observed termination. They compare PIDs only when the application's XCTest debug-description header exposes both values; unavailable PID evidence is recorded without a same-process assertion. No private PID API is used. Simulator state cannot prove physical-device suspension safety, and this isolated fixture bypasses the production App Group migration/ownership path; real-device ownership/lock and Release-performance acceptance remain separate. Retain pre/post scope context, positions, lifecycle records, and native result bundles before any preparation of the next case.

Lifecycle records are enabled only by `__DEV__` plus the controlled fixture scope. They contain page IDs, tags, readiness, observed position and completion phases, without article content or session credentials. `native-detach-completed` records completion of the real adapter command; it is not a claim about unrelated resource ownership or network cancellation. Actual native execution and comparison remain pending until a per-case device report is saved.
