# Original iOS Compose capture fixture

This isolated simulator application compiles the checksum-pinned original common and iOS Kotlin UI, original resources, original iOS reader, and the original native UIKit/Compose integration. It uses the same synthetic `scenarios.json`, article fragments, locale choice and settings as the Android source and Expo fixtures. It is a baseline preparation driver, not a replacement application or a statement that visual acceptance passed.

The source checkout is read only. `../prepare-source-ios.py` reuses the closed public source manifest verification and writes a new `slax-source-ui-fixture-*` directory under the temporary directory. It never evaluates original Gradle/Xcode configuration or reads signing, credentials, environment, service configuration or production App Group files. Every copied pinned source file stays byte-identical. Its marker records the complete overlay digests, excluded platform factories and explicit fixture differences.

The build templates use the original public Kotlin/Compose and SDK dependency versions already used by the Android source fixture. Firebase, Google bootstrap, StoreKit, outbound sharing and production DataStore factories are excluded from compilation and receive narrowly scoped fixture implementations. The unique identity is `app.slax.reader.sourcefixture`; there are no production App Group entitlements or real provider/purchase operations. External actions explicitly fail instead of making a request.

The original `WebViewHelper.ios.kt` remains in the copied input set. A separate compiled derivative adds the prepared `WKContentRuleList` to both original WebView constructors and rejects its two Safari handoffs. Original layout, selection menu suppression, scroll observation, native offsets and custom URL scheme handlers remain intact. UIKit compiles the HTTP/HTTPS/WS/WSS blocking rule before Compose or any original WKWebView can mount. The reader API/SSE uses the existing pure Ktor core fixture engine; custom scheme cache misses cannot open a socket. Other native image consumers can receive only exact prepared synthetic artwork through the fixture URL protocol. HTML also contains the restrictive fixture CSP. YouTube network/provider playback remains pending.

The first real Kotlin compilation identified the original KVO observer's dependency on a custom `platform.foundation.NSKeyValueObservingProtocol` interop namespace. The sanitized template supplies a narrow public Objective-C protocol declaration with that expected package, leaving the original KVO implementation unchanged. The compiler also opts in to `ExperimentalForeignApi` for unchanged original interop calls. These compatibility adjustments are recorded in the input marker; the pinned originals remain byte-identical.

The Reader adapter uses the concrete source User/Subscription DAOs. It waits for the same prepared rows that a preceding Library visit would have loaded before mounting the unchanged Reader. This preparation prevents the original lazy `WhileSubscribed` flows from capturing user ID zero or an initial null subscription solely because the driver opened Reader directly. Metadata records this lifecycle difference. Programmatic DOM selection, comments, overview, outline and gallery preparation does not prove native touch, handles, keyboard, dismissal or back gestures.

Stage public inputs:

```sh
python3 apps/mobile/fixtures/prepare-source-ios.py \
  --source /absolute/path/to/slax-reader-client \
  --output /tmp/slax-source-ui-fixture-ios-a
```

After the coordinated native build slot is available, use the installed public Gradle distribution against that sanitized stage, with one worker:

```sh

  :composeApp:linkDebugFrameworkIosSimulatorArm64
node apps/mobile/fixtures/source-ios/build-app.mjs --project /tmp/slax-source-ui-fixture-ios-a
```

The packaging driver verifies overlay digests, links the real Kotlin framework with a small UIKit launcher, embeds the original prepared Compose resources and signs only with the public local ad hoc identity. It does not install or launch a simulator. Use only a simulator explicitly allocated by the native acceptance owner; never terminate or mutate an unrelated simulator or build.

Launch arguments are `--scenario <shared-case>`, `--fixture-locale en|zh`, and optional `--fixture-action-index <index>`. Each selected Reader action starts from fresh state, preventing retained sheets from masking the next capture. Bound original routes are Library, Settings, Feedback, About, DeleteAccount, Login and personal/collection Reader. Unsupported routes/actions fail explicitly; source StoreKit/provider/share flows and native exit drivers remain pending.

The ordinary Settings, Feedback and About bindings call the unchanged source screens. DeleteAccount also calls the unchanged screen and supplies only the shared local notice to a real WKWebView. That legal-document adapter dispatches actual native PageLoaded/Scroll callbacks, including the original measured scroll callback 300ms after load. It never assigns the DeleteAccount bottom/readiness state or injects a scroll. Its preparation waits for the actual DOM-ready callback and positive native content/viewport measurements. These new legal-screen callbacks and DeleteAccount binding are prepared but have not yet been compiled or captured on iOS; they cannot be counted as native acceptance. The original Android-only connectivity reflection diagnostic is explicitly omitted from the iOS Reader derivative, without replacing its concrete original coordinator.

An optional `--fixture-reader-step top|anchor-middle|anchor-then-top` is limited to the initial `reader-mixed` route with action index `-1`. The default is `none`. A separate Swift driver waits for the genuine current-launch prepared state and twenty initial readonly samples, checks the actual original DOM/mark bridge, then posts only the existing `scrollToTop` or `scrollToPosition(0.5)` native bridge event. The sequence observes twenty anchor samples before posting the original top event and observing twenty further samples. Unchanged source Kotlin owns the resulting scroll command. `fixture-reader-step.json` records the input and observations afterward. The driver never directly calls `window.scrollTo`, sets a native offset, or changes the initial saved position. An observed result is programmatic preparation evidence; it does not prove native touch or target parity.

The driver writes `Library/Application Support/fixture-status.json` and `fixture-viewport.json` in its unique container. `state: prepared` requires actual source DAO/DOM readiness and the real command callback; elapsed time cannot become success. A bounded UIKit observer recursively finds the original WK view after a current-launch matching prepared status and writes twenty readonly offset/inset/content/viewport observations to `fixture-reader-geometry.json`. It does not inject JavaScript, set an offset, or change the original observer. A frame is accepted only after the capture owner separately verifies the foreground application, absence of unrelated overlays, expected visible state, input digests, geometry and source/target comparison.

`control/` is a separate small XCTest UI target with unique fixture identities. It activates only the source fixture, checks the inspected Open-in-Slax-Reader title and exact Cancel/Open pair, and taps only Cancel, at most three times. Unknown alerts fail. Both capture tests require the source foreground and zero system/source alerts. The initial-frame test also requires the actual fixture title; the scroll-step test requires exactly one visible WK view with the expected full-screen size because the title can scroll out of view. The separate current-launch prepared status and readonly step record must still be inspected before accepting a frame. Runs must name the explicitly allocated simulator, use `-parallel-testing-enabled NO` and `-maximum-concurrent-test-simulator-destinations 1`; never allow a second simulator clone. This narrow native input does not prove Reader touch, selection, keyboard, navigation or gallery behavior.
