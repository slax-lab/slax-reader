# Source-valid legacy rows for visible upgrade acceptance

The historical minimal producers and their reports remain unchanged. Their bookmark has no `archive_status` or nested `bookmark.status`, and their comment has no `user_bookmark_uuid`; those rows are useful for storage/queue tests but cannot prove normal inbox navigation or visible annotations. `visible-legacy-inputs.json` defines an additional synthetic scenario, written by the same genuine Kotlin 1.14.1/core 0.5.1 and AndroidX DataStore 1.2.1 producer.

`tooling/visible-producer-project.mjs ios` or `android` creates a new, marked standalone project directly under the system temporary directory. It reads only the explicit public file whitelist after checking the historical source digests. No existing source/build directory, database, device or report is modified. It copies no dependency cache, generated native artifact, operator configuration or signing material. Android references the Expo-generated public debug keystore opaquely through the existing `expoMobileDir` property; the generator does not open or copy that file. The generated project limits Gradle workers and both Java heaps to one worker/1 GiB. Build and device execution are separate actions.

The genuine old SDK still writes exactly two two-operation transactions: tag PUT, bookmark PUT; bookmark PATCH, comment PUT. Original logical IDs and all original DataStore preference assignments remain byte-identical in the generated Kotlin source. Local-only JSON and the cached article do not add CRUD operations. The original producer's database close precedes publication of the marker; an additional scenario/input SHA identifies the new sample without changing `fixtureVersion=1`.

`node --experimental-strip-types --test apps/mobile/tests/data/visible-producer.test.mjs` checks the full rows against the actual production inbox/detail/comment repository queries using host SQLite, builds the actual Reader mark model, verifies the cached selection range, and rejects missing row/annotation fields and changed/symlink project inputs. It also confirms the original public source hashes/preferences/SDK dependencies and four-operation/two-transaction source structure remain intact. These are host checks, not evidence of a native SDK write, upgrade, visible screen, publisher package or TestFlight upload.
