# Mobile build inputs

Keep local iOS and Android build inputs in this directory, outside the native projects regenerated by Expo. Only this guide and `.env.example` are tracked. Service files, signing files, and `.env` remain ignored.

```text
deploy/mobile/
  .env
  ios/
    GoogleService-Info.plist
  android/
    google-services.json
    slax-reader.release.jks
    slaxreader-publish.json     # optional existing Google Play upload account
```

Extract the operator ZIP **at the repository root** to restore these paths. Do not extract it inside `apps/mobile` or inside `deploy/mobile`.

Copy `.env.example` to `.env` only if `.env` does not exist. Fill `SLAX_ANDROID_KEYSTORE_PASSWORD`, `SLAX_ANDROID_KEY_ALIAS`, and `SLAX_ANDROID_KEY_PASSWORD` with the original publisher key's values. The archive does not invent or recover unknown passwords. Inspect the existing alias interactively with:

```sh
keytool -list -v -keystore deploy/mobile/android/slax-reader.release.jks
```

The command prompts for the keystore password. The key password equals the keystore password only if that was the original configuration. Keep signing passwords out of public Expo variables.

The root `pnpm mobile -- <command>` entry loads `deploy/mobile/.env` for native preparation, development, and build/release commands. Expo configuration and direct native build/release scripts use the same loader. Existing shell/CI values override the file. The three default Firebase/keystore paths are detected automatically when their files exist; explicit path overrides resolve relative to the repository root, independent of the caller's working directory. File values are parsed as dotenv data without shell evaluation or variable expansion. API, Web, and Extension environment files are not read.

Tests, type checking, JavaScript bundle checks, and controlled fixture projects skip local configuration. Set `SLAX_MOBILE_NO_LOCAL_CONFIG=1` to explicitly disable local discovery for another invocation. A native command with no local files retains the unconfigured development path; signed releases still reject missing credentials and invalid version metadata.

## Development session

`pnpm mobile -- dev`, `pnpm mobile -- ios`, and `pnpm mobile -- android` optionally point the development bundle at a LAN API, PowerSync instance, and the human's test account:

```dotenv
SLAX_MOBILE_DEV_API_URL=http://192.168.1.10:8787
SLAX_MOBILE_DEV_POWERSYNC_URL=http://192.168.1.10:18080
SLAX_MOBILE_DEV_TOKEN=<reader session JWT>
# Optional; defaults to the API hostname on port 3000.
SLAX_MOBILE_DEV_WEB_URL=http://192.168.1.10:3000
```

Set all three required keys together. Without them, development keeps the normal provider sign-in and default origins. With only some of them, the development command stops with the missing key instead of silently mixing origins. A complete session replaces the API, beta API, web, and PowerSync origins in the development bundle, installs the supplied session through the normal account lifecycle before protected requests, and relays LAN addresses to the matching loopback services on this machine. Changing `SLAX_MOBILE_DEV_API_URL` signs out and clears the local account data on the next development start instead of migrating it to the new origin; reusing the same origin keeps the existing local database. Development starts also use the native fresh-storage slot: they open the current React Native database directory directly without scanning legacy Kotlin files, running adoption/upgrade verification, or taking the exclusive cross-process ownership lease. That lets a JS hot reload reopen the database instead of failing on a stale native lease. Rebuild the native app once after this tooling change to install the updated method; release builds keep the full adoption barrier and ownership lease. The relay rewrites the forwarded `Host` header to `localhost` so local API host routing accepts requests that arrive through the LAN address. The token never enters `EXPO_PUBLIC_*` variables or tracked files; Metro keeps a private generated copy under ignored `.local/mobile-development/`.

- The session affects only development-serving commands: `dev`, `ios`, and `android`. Their Release variants (`--configuration Release`, `--variant release`, `--release`) and build, configuration, bundle, test, and fixture commands ignore these keys even when they are present. Restart the development command after changing the keys; Metro reads the session when it starts. Remove the keys to return to the normal defaults; the app then requires a regular sign-in for the selected environment. The supplied credential is personal debugging input: do not commit it or reuse it for release builds.

Maintain public version metadata in `apps/mobile/package.json`, independently of this local directory:

```json
{
  "version": "1.0.25",
  "buildNumber": 766,
  "previousBuildNumber": 765
}
```

This represents `1.0.25(766)`. Both native platforms and the iOS share extension use these fields; `.env` and the former `SLAX_MOBILE_VERSION`, `SLAX_MOBILE_BUILD_NUMBER`, and `SLAX_MOBILE_PREVIOUS_BUILD_NUMBER` variables do not override them. Keep `version` as a valid three-part package version, `buildNumber` as a positive integer, and `previousBuildNumber` as a lower confirmed build bound. Before another store release, choose a new build greater than all already published builds and update the previous bound accordingly. Keeping build 766 records the latest delivered version; it does not authorize republishing that build. Controlled fixtures retain their separate `1.0.0(1)` metadata.

After updating the package metadata when needed, run Android preparation/builds from the repository root:

```sh
pnpm mobile -- prebuild --platform android
pnpm mobile -- build:android --release bundleRelease --max-workers=1 --no-parallel --no-daemon
```

For iOS, configure the Apple team in `.env` and use the same package version metadata with the existing guarded release workflow:

```sh
pnpm mobile -- prebuild --platform ios
pnpm mobile -- pods
pnpm mobile -- archive:ios --output /absolute/path/to/fresh-archive-run
```

iOS signing continues to use the existing Xcode account, Keychain identities, and provisioning access. This directory does not replace the Keychain or fabricate signing certificates/profiles. The optional Android upload-account JSON is retained for operator use; the local build commands do not read it or publish to Google Play. Archive, export, and upload remain separate explicit commands. See [mobile release guidance](../../docs/mobile/release.md).
